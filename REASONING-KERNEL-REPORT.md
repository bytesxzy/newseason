## 3. What each component does

**Kernel (`c4-reason-kernel.js`).** `Hypothesis` (domain, representation,
assumptions, evidence, constraints, latent state, program, predictions,
residual, diagnosis, complexity, lineage with parent / mutation / depth /
residual before and after / assumption added or removed). `mdlScore` puts
every term in bits: program length + 2 bits per assumption + residual
exceptions + log2(10) per invariant violation + repair-path bits. `Frontier`
is bounded with a per-cluster cap and evicts from the most crowded cluster,
so diversity survives. `refine()` is the loop: evaluate seeds, route exact
ones through the adapter's verifier into a bounded exact pool, then let a
`MetaController` choose REFINE_BEST / REFINE_DIVERSE / ABSTRACT_RESIDUAL /
CHANGE_REPRESENTATION / EXPAND_PROGRAM / SIMPLIFY_PROGRAM / BACKTRACK / STOP
from explicit state features (best residual, stall count, exact count,
cluster count, budget left, recurring diagnosis) with documented priors,
learned weights and observed payoff. Children survive only if they improve
the residual, are >= 2 bits simpler at no residual cost, or open a new
cluster. Duplicate behaviour keys are rejected (cycle detection); depth,
steps, children per step and stall length are bounded. `discriminate()`
runs hypotheses on label-free probes; `calibrate()` turns evidence
(independent derivations, disagreements, verifier passes/failures,
contradictions, assumptions, cross-validation, margin, knowledge
completeness) into log-odds with each weight stated as a likelihood ratio.
`ReasoningGraph` holds propositions as KNOWN / DERIVED / ASSUMED / UNKNOWN /
CONTRADICTED, propagates refutation to dependents, and diagnoses failures as
missing knowledge / contradiction / unsupported assumption. `stageOf` gives
tentative -> candidate -> persistent -> retired.

**ARC residuals (55).** Quick pass per candidate (cell errors, normalised
error, bits, under/excess/wrong change relative to the input, invariant
violations, cluster signature). Full diagnosis on demand: dims relation
(orientation, scale, tile, crop, extend), consistent colour substitution,
whole-grid orientation/translation, error regions, object correspondence
(moved, recoloured, reoriented, missing, extra, count, holes, relation
flips), the input-object class separating mishandled from handled objects
in every pair, and the change-set class separating correct from excessive
change components. A diagnosis is `strong` only if consistent across pairs.

**ARC repair (56).** A near-miss is `base >> tree`; typed near-misses have
no base so every node is editable. Mutations: parameter substitution,
operator substitution, predicate inversion, composition insertion (append /
prepend), deletion, reorder, literal colour -> semantic role, selected <->
forall objects, object-class restriction, change masks, change-set
filtering, fitted closers (colour, object, and context tables). Children are
ordered by diagnosis relevance plus the learned repair table.

**Refinement stage (57).** Runs on time the schedule left unused (plus the
evaluation reserve if nothing executable exists). Only programs that
reproduce every demonstration and execute on every test input are emitted,
as family `repair`, after an independent re-verification; repairs that
duplicate an existing exact prediction are dropped. Repaired parameters
are refitted leave-one-out (tables re-solved from held-in pairs).

**Counterfactuals (58).** When exact explanations disagree about the test,
probes (colour swap, remove, nudge, swap objects) measure divergence and
fragility; a fragility cost of at most 4 bits is the only ranking effect.

**ARC-3 (`c4-arc3-world.js`).** Perceive entities; delta between frames;
agent identified by action-correlated motion; action rules per
displacement with staged confidence; a non-move is diagnosed against the
colours the agent has actually entered and repaired as a condition
("moves right unless the target is colour 5"), not a contradiction;
teleports, contact effects, hazards and goals learned from events; utility
= goal value x P(goal) + uncertainty-weighted information gain + novelty -
hazard risk - cost, with a futility memory for actions that changed nothing
from the same state; BFS planning over the learned model; cross-level memory
keeps only coordinate-free mechanics and reloads them as candidate (not
persistent) rules.

**LM / HLE-style (`c4-lm-problem.js`).** Problems are composed from an intent
(cue lexicon) and extracted mathematical objects. Kinds: linear/polynomial
equations, linear systems, derivatives, definite integrals, combinations,
permutations, gcd/lcm, primality, factorisation, modular powers, dice and
coin probabilities, series, shortest paths, multiple choice, arithmetic.
Each has 2-3 methods sharing no code and kind-specific falsifiers. Also:
derivation-chain checking with step localisation, classification and
repair; knowledge-vs-reasoning analysis; the visual-fact interface; exact
BigInt rationals and polynomials, Miller-Rabin, Dijkstra / Bellman-Ford, a
small CSP solver, Simpson quadrature.

## 6. ARC evaluation (actually run)

3 s per task, 3 workers, bundled corpus: 400 `arc1_` tasks (the ARC-AGI-1
public training split) and 150 `arc2_` tasks. These are development
measurements on public data, not held-out evaluation. Each engine was run
twice to expose wall-clock noise (`measurements/arc-bench-summary.json`).

| | top-1 | top-2 | oracle retained | task-seconds | errors |
|---|---|---|---|---|---|
| ARC-1 baseline, run 1 / run 2 | 223 / 222 | 228 / 227 | 228 / 227 | 966 / 963 | 0 |
| ARC-1 final, run 1 / run 2 | 225 / 224 | 229 / 229 | 230 / 230 | 995 / 995 | 0 |
| ARC-2 baseline, run 1 / run 2 | 51 / 51 | 53 / 53 | 55 / 55 | 354 / 355 | 0 |
| ARC-2 final, run 1 / run 2 | 51 / 51 | 54 / 54 | 56 / 56 | 372 / 373 | 0 |

No task exceeded the budget beyond the harness's normal overrun; no ERROR
records in any run.

**Attribution, stated plainly.** The refinement stage won 0 tasks in the
final runs. The ARC-1 top-1 gains are programs of the existing `cellwise`
family. Controlled reruns showed those tasks flipping between solved and
unsolved under BOTH engines: `celltree` receives a ~100 ms slice as the
48th of 53 scheduled actions and its job takes about that long. I therefore
do not claim the +2 on ARC-1 as an effect of this work; the ARC-2 top-2 /
oracle +1 is likewise too small to attribute.

## 10. Implemented, measured, rejected / not implemented

- **Starved-family retry (rejected).** 380/400 ARC-1 tasks have a family cut
  off by its slice while 261 of them finish with budget left. Giving the
  leftover to starved families in equal shares measured ARC-1 223 / 222,
  ARC-2 50 / 51 at +10% time: no better, so it was reverted (commit
  history keeps it). With ~8 starved families per task an equal share is the
  same ~110 ms slice they already had.
- **Real ARC-AGI-3 integration:** no ARC-AGI-3 environment or API is
  available here; the adapter is tested on synthetic environments only.
- **Perception:** the multimodal path is an interface tested with structured
  facts; there is no image parsing.
- **Symbolic algebra** is polynomial-only (no symbolic trig/log/exp);
  unit-aware problem reasoning is left to the existing operator library.
- **Lineage** records parent, mutation, depth, residual before/after and
  why; ARC mutations do not populate assumption-added/removed.
- **The family planner (06)** was not retrained; the new meta-controller is
  trained on the synthetic curriculum only.

## 11. Strongest remaining bottlenecks

1. **Near-miss supply.** Only 9 of ~53 families (and typed synthesis) emit
   failing candidates; the rest filter internally. In the final ARC-1 run,
   137 tasks had no executable candidate and refinement found an exact
   program for none. Typed near-misses are usually more than three edits
   away.
2. **Scheduling.** Knife-edge slices decide several tasks per run.
3. **Wasted children.** 65,021 of 105,284 proposed children (62%) were
   behavioural duplicates; kept 13,793, wasted 26,353.
4. **Language coverage.** Prose word problems, and other routes answering
   off-topic with high confidence.
5. **Knowledge.** HLE is mostly expert knowledge this project does not hold.

Profile of the final ARC-1 run (`measurements/arc-profile-arc1.json`):
exact programs came mostly from closers (30), operator substitution (12),
local appends (9), dihedral appends (6), masks (5) and change filtering (4);
mean repair depth 1.14; the most frequent diagnoses were missed_change,
wrong_dims and unhandled_object_class; the controller chose REFINE_BEST
6,674 times, CHANGE_REPRESENTATION 756, BACKTRACK 370, SIMPLIFY 204,
ABSTRACT_RESIDUAL 172, REFINE_DIVERSE 74.

Repair policy (`measurements/arc-curriculum.json`): recovery of corrupted
synthetic programs at a 4-operation budget 66.0% -> 72.4% with the learned
policy (generalisation to the held-out input 62.9% -> 69.3%); at 2
operations 59.4% -> 62.5%; with a generous budget both reach ~87%.

ARC-3 synthetic (`measurements/arc3-synth.json`, 90 levels): 81.1% of
levels completed with cross-level memory vs. 64.4% without; later levels in
18.0 steps vs. 23.7; action-semantics accuracy 0.91.

## 12. Next highest-value improvement

Make the high-yield internal searches (celltree, objproc, relproc, objchain,
rewrite, enumerate) export their best failing programs *with structure*
through one interface, so the refinement kernel receives near-misses from
the families that actually solve ARC tasks, and train the family planner to
allocate slices from the timeout statistics now recorded in every result.
The repair machinery works on synthetic near-misses (87% recovery); on real
ARC it is starved of good seeds.

## 13. Follow-up: phrasing, metaphors, word problems, ordinary questions

Section 7 ended on three open problems: prose word problems ("2 times a
number plus 11 is 15", "a pair of dice", "largest integer dividing both"),
other subsystems answering those off-topic with high confidence, and
brittleness to idiomatic and metaphorical phrasing. This follow-up
addresses all three with general mechanisms. No question string, idiom ->
answer table or per-entity rule was added anywhere.

**What was added (all edits in place, no file rewritten):**

- `c4-lm-problem.js`: a compositional grammar of quantitative English.
  - Operand order flips ("5 less than 3x", "4 subtracted from x").
  - Prefix operators ("the sum of A and B").
  - Postfix chains ("doubled and then increased by 7").
  - Imperative chains on a running value ("triple a number and subtract 4",
    "add 13 to it").
  - Passive voice ("when 8 is added to five times a number, the result is 48").
  - Purpose infinitives as equality ("... add 9 to get 25").
  - Two-unknown systems ("sum ... is 30 and their difference is 6").
  - Number words, fractions ("three quarters of") and collectives
    ("a pair of", "a dozen").
  - Descriptive readings: gcd/lcm by description, pairwise counting (choose 2),
    remainders, range sums, single-die and multi-die probability.
- `c4-lm-reason.js`:
  - Typo-tolerant term unification in syllogisms (edit distance with
    distinct-term constraints).
  - The typographic percent rule: "15% 240" is a percentage, "15 % 240" is modulo.
- `c4-lm-core.js`:
  - Contractions of function words ("what's", "who's") are function words,
    no longer proper-noun "entities". This was the cause of answers like
    "I don't have anything reliable on What's".
  - Polite wrappers are stripped to a fixpoint ("hey, could you tell me ...").
  - "That's cool" is an acknowledgement.
- `c4-lm-memory.js`: a message the problem reader parses as a problem is not
  a statement about the speaker ("I double a number ..." was being stored as
  a personal fact).
- `c4-lm-realize.js`: a participial relation value ("described by Charles
  Darwin") is used as the predicate instead of being wrapped in another verb.
- `c4-lm-lexicon.js`: about 95 ordinary dictionary entries, including
  figurative senses (tongue = a language; pen = a writer; seat = where a
  government sits; hood = inner workings). Existing entries are never
  altered. These are word senses, not answers; the metaphor results below
  depend on them.
- `c4-lm.js`, **deliberation**. When the first answer is weak (no answer, a
  compositional guess, small talk to a request, a word definition for a
  who/where/when question, less than two thirds of the question accounted
  for, the wrong answer type, or a stated number left unused), alternative
  readings are generated:
  - entities the knowledge base can spot in the words;
  - relations named directly, or through another sense of a word, chosen
    by gloss overlap with the rest of the sentence (the Lesk criterion);
  - words whose dictionary gloss the sentence paraphrases ("turn to ice"
    is the gloss of "freeze"), with the entities' types as context;
  - person relations for "who" questions;
  - the entity's own stored facts, ranked by coverage;
  - content retrieval;
  - for numeric fragments, a search over the missing connective, keeping
    only readings whose worked steps use every stated number.

  Every candidate is answered by the ordinary resolvers and scored on one
  scale: did a resolver answer, how much of the question the answer
  accounts for, answer-type fit, and reading cost. The first answer is
  replaced only by a margin of 0.75.

  There are two honesty rules:
  - An answer about a known thing to a question whose subject is a name
    nothing knows is withdrawn ("freezing point of zorbanium" used to
    return water's freezing point).
  - A request about an unknown named thing gets "I don't have that"
    instead of small talk.

  Cost limits: at most 10 readings, a 300 ms budget, and nothing runs for
  verified compute/reason answers, fresh-information questions or
  dictated formats (lists, one word, N sentences).

## 14. Follow-up: comprehension, conversation awareness, ARC re-framing

**Comprehension stage** (`c4-lm-comprehend.js`, new). It runs on every
question of 80 words or fewer:
1. **Every word and phrase gets a gloss.**
   - Knowledge-base phrases get the entry's definition.
   - Content words get the lexicon sense chosen by gloss overlap with the
     rest of the question.
   - Closed-class words get their grammatical role; numbers and units get
     their quantity.
   - Unknown words are flagged.
2. **Quantities and rates are read.** This covers "60 miles an hour", "12
   litres every 3 minutes", "20 pages per minute", and dictionary-defined
   abbreviations ("mph" is glossed "miles per hour").
3. **The asked dimension is found.**
4. **A one-line summary and a research query are built.**
5. **Quantitative questions are derived by dimensional analysis.** The solver
   searches exponents over the stated quantities, plus at most one quantity
   the knowledge base holds for a mentioned thing, which is declared as an
   assumption. When the question does not fix its answer, it names exactly
   what is missing, gives the relationship, and states the rate per unit of
   the missing extent.

The summary query drives research:
- **Several documents, strictly on topic.** Sentences are ranked by coverage,
  and agreement across documents counts.
- **"What/which N" instance research.** The answer is the N that the
  documents about the rest of the question mention; the connecting sentence
  is quoted.
- **The federation.** It gets the summary as an extra query when the network
  is available.

**Conversation awareness** (`c4-lm.js`):
- The discourse keeps a record of each turn: normalised words, content stems,
  the requested form, the subject, the answer, and whether it was a real
  answer.
- **Repeats.** A question matching an earlier one (same words, or 80%
  content-stem overlap with the same requested form) is re-read without
  dialogue context, so it cannot drift. The reply depends on the last
  answer:
  - After a non-answer, the repeat is acknowledged with its count and the
    limit is stated.
  - A real answer is given again with the repeat acknowledged.
  - A changed answer is introduced as a second attempt.
- **Reactions.** Interjections are a closed class. A content-free message
  answers the last exchange, never its topic words:
  - After a non-answer, the reaction is read as noticing that.
  - Recurring reactions to non-answers on the same subject are named as
    going in circles.
  - Consecutive reactions are counted.
- **No self-repetition.** The system does not repeat its own sentence. The
  realiser's canned "As I said:" openers were removed.
- **Parser.** "how do/does X work" is now a mechanism question about X.
